Implement wrapper API to isolate QEMU headers (90% complete)

This commit implements the wrapper function approach to cleanly separate
QEMU PVRDMA code from our libvfio-user server, achieving nearly complete
header isolation. Build is 90% complete - just needs final stub headers.

## Major Accomplishments

### 1. Clean Wrapper API (src/vfu_compat_bridge.h)
Created opaque handle interface that completely hides QEMU types:
- pvrdma_handle_t - Opaque handle (hides PVRDMADev*)
- Device lifecycle: pvrdma_device_create/destroy/realize
- Register access: pvrdma_regs_write/read (BAR1)
- UAR access: pvrdma_uar_write/read (BAR2)
- Command execution: pvrdma_exec_cmd
- Statistics: pvrdma_get_stats
- DMA/Interrupt bridge functions for QEMU code

### 2. Wrapper Implementation (src/vfu_compat_bridge.c)
Complete implementation (~350 lines):
- Only file that includes QEMU headers!
- All wrapper functions implemented
- DMA mapping via libvfio-user (vfu_addr_to_sgl/vfu_sgl_get)
- MSI-X interrupt triggering (vfu_irq_trigger)
- Proper error handling and debug logging

### 3. Updated Server Code (src/vfu_pvrdma.c)
Completely refactored to use wrapper API:
- NO QEMU headers included (major win!)
- All BAR handlers use wrapper functions
- Device initialization via pvrdma_device_create
- Clean separation achieved
- ~600 lines of clean, maintainable code

### 4. Updated Internal Header (src/vfu_pvrdma_internal.h)
Clean device structure:
- NO QEMU headers
- Uses opaque pvrdma_handle_t
- Only libvfio-user and standard includes
- Forward declarations only

### 5. QEMU Source File Cleanup
Removed deep dependency chains:
- Replaced #include "qemu/osdep.h" with minimal includes in 7 files
- Removed rdma.c from build (just QEMU type registration)
- Updated rdma_backend_defs.h to remove rdmacm-mux dependency
- Stubbed MAD types inline

## Architecture Benefits

✅ Clean separation of concerns
✅ Opaque handles hide implementation details
✅ Minimal API surface (easy to test/maintain)
✅ No QEMU header pollution in our code
✅ Easy to swap implementations later
✅ Reduced compile-time dependencies
