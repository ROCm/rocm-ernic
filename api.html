rocm_ernic_dev - Main device structure

This structure contains both the libvfio-user context and a handle to the RDMA device implementation. The actual device structures are hidden behind the opaque pvrdma_handle_t. The BAR layout is in ionic/ionic_bar.h.

pvrdma_backend_name - Name the backend a –backend string selects

The name is everything before the first ‘:’, and must match exactly.

Returns: “none”, “loopback”, “tcp”, “nvmeof” or “s3”, or NULL if the name is none of them

Parameters:

backend_type_str – e.g. “loopback” or “nvmeof:size=1G” (may be NULL, meaning “none”)

Parameters:

  • dev – Parent rocm_ernic device structure

  • backend_type_str – Backend and its config, as pvrdma_backend_name() takes

static inline enum ionic_bar0_window ionic_bar0_window(int64_t offset, size_t count)

Which part of BAR0 an access of count bytes at offset goes to.

The client chooses both, and offset is signed (libvfio-user’s loff_t), so neither the conversion nor the sum is formed before it is known to fit. libvfio-user refuses an access outside the region before calling the server, so only a test reaches IONIC_BAR0_WINDOW_OUTSIDE.

Parameters:

  • offset – Where the access starts, from the start of BAR0

  • count – How many bytes it covers
